These are buildable test apps that run in CI to confirm correct api operation.

|name|tests|
---|---
api-test-lwsac|LWS Allocated Chunks api
api-test-lws_struct-json|Selftests for lws_struct JSON serialization and deserialization
api-test-lws_tokenize|Generic secure string tokenizer api
api-test-demo-plugins|The demo plugins served by lwsws and the test server keep what they send to other people's browsers valid: lws-mirror relays a TEXT message split mid-character as one whole message and BINARY as BINARY, refuses a too-large message without relaying any of it, and idle connections on every named instance can't lock anyone out of the default one; lws-status sends valid UTF-8 JSON with hostile User-Agents; dumb-increment sends each connection 20 numbers a second however many there are
api-test-ws-server-examples|The ws-server minimal examples' protocols, built as the examples build them, stay safe whatever a peer sends: pmd-corner sends its corner case for "/1", and nothing for URLs naming no corner case ("/-1", "/0", "/6", huge numbers, trailing junk), without reading outside its table
api-test-wsmsg|`lws_wsmsg_append()` queues whole messages on an upstream buflist2, holding a fragmented one on its source's private buflist2 until its EOM, while other sources' messages carry on past it; the upstream limit holds, 20000 queued segments come out intact, and `lws_wsmsg_destroy()` frees what's held
api-test-stdin-cmdline|stdin folded into the commandline by `lws_system_adopt_stdin(cx, LWS_SAS_FLAG__APPEND_COMMANDLINE)`: a last token with no trailing newline resolves as a complete string, as a --switch=value, a bare --switch, a spaced value or a non-switch arg
api-test-region|Scratch buffer region ownership tracking: claims, overlaps, trims, hand-overs and stale handles
api-test-sansio-link|The sansIO half linked alone, with every unresolved symbol an error (`-DLWS_WITH_SANSIO_LINK_TEST=1`), loads and runs
api-test-random-prng|Fault injection's seeded PRNG in place of the platform random source: same seed, same bytes, a known vector, independent of other faults (`-DLWS_WITH_SYS_FAULT_INJECTION=1`)
api-test-sul-wait|A loop with nothing to do but wait for its next timer sleeps until the timer is due: timers at intervals with sub-ms parts take a turn or two each, not a run of zero-wait turns through the last ms before each, on the default loop and on libuv
api-test-evlib-custom|An app's own event lib (`info->event_lib_custom`) is bound with the app's own loop object and gets every fd back at destroy; run again with `LWS_EVLIB=uv` in the environment, which must not displace it
api-test-fts|LWS Full-text Search api
api-test-gunzip|`lws_upng_inflate_data()`: gzips from the system gzip and stored, fixed huffman and empty blocks in any order inflate whole however the input is split; a final stored block ends the stream, every truncation wants more input, a bad trailer CRC32 or ISIZE is fatal (G-504)
api-test-gencrypto|LWS Generic Crypto apis
api-test-srtp|SRTP / SRTCP (`-DLWS_WITH_WEBRTC=1`): session key derivation matches the RFC 3711 B.3 vectors and AES-CM the B.2 keystream on the TLS library in use; RTP and SRTCP round trip for SSRCs with the top bit set, the E bit is set on the SRTCP index, and tampered or replayed packets are refused (G-456)
api-test-jose|LWS JOSE apis
api-test-dnssec-monitor-reissue|dnssec-monitor proxy's per-cert "Force reissue": answered locally, reaches LWSSMDCL_CERTS as the documented message, non-DNS names and fqdns outside the domain refused
api-test-dht-msg-parse|DHT RPC wire message parser, incl. hash token charset and NOTIFY domain-name gates
api-test-dht-seq-flood|A flood of forged first data chunks fills the DHT's 64 sequencers but never destroys one in use: a queued message to a peer survives it and completes; when all 64 hold unacked messages a new peer is refused, each reports WRITE_FAILED, and a resend from that handler is taken (G-496); a send from WRITE_COMPLETED can't recycle the sequencer calling back (G-519); 64 proven sessions that only resend stop holding their slots after a few seconds, and a newcomer is taken (G-518)
api-test-auth-dns-dnsbl|auth-dns plugin DNSBL pending-query lifetimes (F-054): late resolver replies and client disconnects vs the 5s dnsbl timeout
api-test-auth-dns-zonedir|auth-dns plugin local zone-dir trust policy (F-055): missing pvo / world-writable / symlinked dirs and foreign-uid or wrong-shape zone files refused; zones handed over by dht-dnssec installed only if exactly their domain's (G-117) and signed and in date (G-505); a query whose zone fetch is given up (G-224); query-driven zone fetches rate limited, and a query for a zone being fetched waits on that fetch (G-508), per source host, so one source's queries leave another's fetches (G-535)
api-test-dht-dnssec-fetch-fanout|dht-dnssec zone fetches against a routing table bigger than a round (G-508): a fetch asks 8 nodes and the bootstrap target, its retries the next ones, never one twice; with every DHT sequencer in use its sends are refused, no host counts as asked, and an early round asks them once sequencers free up; an early round asks only what its full round left, and a fetch whose list of hosts asked is full asks no new one rather than forgetting one (G-534)
api-test-auth-dns-glue|auth-dns plugin zone lookups by owner name (G-288): a referral to a 100-NS cut in a zone of 4000+ RRsets carries all its glue for a few compares per NS RR, and owner lookups are a few compares each
api-test-auth-dns-names|auth-dns zone names (G-474): wildcard owners and NS targets are kept and go out on the wire as `*` labels, RFC 1035 escapes in owners are resolved and quoted `;` / parentheses are text, and names that would encode an empty label, a misplaced `*`, a label needing an escape, rdata escapes, unknown directives or a missing type refuse the zone with an error naming the line
api-test-async-dns-smp|Async DNS with two service threads (`LWS_MAX_SMP` > 1): lookups and raw client connections asked from both threads at once, some of the same names, are each answered and called back on the service thread that asked, whichever thread the answer arrived on (G-526); both threads also make and close chains of raw connections at volume at once from their callbacks, so their wsi are tagged into and out of the context's lifecycle lists concurrently (G-549); run again with `--fd-limit-per-thread 256`, so fds are found by searching each thread's slots of the small lookup table instead of indexing one by fd (G-635)
api-test-quic-smp|h3 over QUIC with two service threads (`LWS_MAX_SMP` > 1): h3 client connections opened from both threads at once fetch a multi-round-trip body each from an h3 server vhost in the process, every callback on the thread that asked, while debug builds assert each connection's QUIC timers fire on its own service thread (G-536); the connections of both threads also offer and replace one shared TLS session cache entry (G-537)
api-test-dht-object-store|dht-object-store plugin transfer slots (G-257): one host only gets a few of them, so another can still PUT; a transfer trickling behind the minimum rate is dropped, and its declared length counts against the quota while in flight
api-test-sshd-userauth|sshd plugin USERAUTH pubkey/sig blob walks (F-056): malformed blobs must be rejected bounded, genuine signatures still authenticate
api-test-sspc-streamtype|serialized client streamtype length cap (F-057): over-long streamtypes refused at sspc create, boundary-length still accepted
api-test-mqtt-unsub|mqtt subscribe/unsubscribe topic count cap (F-058): over-wide or zero topic lists loudly refused at the established-state tx paths, boundary-width unsubscribe still works end-to-end; a two-topic (wildcard and short) unsubscribe with one UNSUBACK leaves the connection holding nothing at close (C-061)
api-test-ss-mqtt|Secure Streams sharing an mqtt connection with an in-process broker: a stream that gives up (DESTROY_ME) from the QoS0 ack or the local SUBSCRIBED lws makes up, or that destroys another stream on the connection while lws walks its streams (queue adoption, PUBLISH delivery, WRITEABLE), is told once and destroyed once, nothing uses it afterwards
api-test-lws_spa|POSTed urlencoded and multipart forms through `lws_spa`, with its own and with lwsac storage: a parameter with no value is present and empty; a multipart epilogue stays part of the request body
api-test-http-attack|Hostile requests (what scripts/attack.sh did, h1 smuggling and slow headers, h2 framing / hpack / flood abuse, traversal out of a file mount) over h1, h2 and h3 are refused, and the server still serves after each
api-test-mtls|A vhost requiring a valid client cert refuses no cert and a cert its CA did not sign, and serves one it did, over h1 and h2 over tls and h3 over quic on the same port
api-test-tls-accept-async|A burst of h1 and h2 tls connections is all served, whether each server tls accept went to the async worker or, its queue full, was done inline: the inline accept completing the handshake must leave the connection reading
api-test-tls-renew|A server vhost that starts without its cert (IGNORE_MISSING_CERT) gets its first tls ctx, and then a renewed one, from lws_tls_cert_updated(), each set up like a vhost's first ctx: h2 is still negotiated
api-test-tls-client-trust|A CA added to one client vhost with `lws_tls_client_vhost_extra_cert_mem()` is trusted by that vhost only: not by a vhost created the same way that shares its client tls ctx, nor by one created like it later; `.client_ssl_ctx_unshared` gives a vhost a ctx of its own to add trust to
api-test-tls-sessions|The client tls session cache keys sessions by an exact vhost / host / port tag: a host name too long for the tag is not cached, rather than cached under a truncated tag a look-alike host would find
api-test-oversized-headers|A request whose headers don't fit the server's header table gets 431 "Oversized headers" over h1, h2 (prior knowledge and tls) and h3, and a normal one after it is served
api-test-h3-header-amplification|QPACK / h3 header "accordion" attacks (thousands of distinct names, 1100 one-byte field lines, a HEADERS frame declaring 16MiB, HEADERS chained after trailers, 1000 one-byte references to a 4KiB dynamic table entry) are refused with 431 or a connection error while lws' heap grows by about what came on the wire; the SETTINGS_MAX_FIELD_SECTION_SIZE an h3 vhost advertises is enforced either side of it
api-test-http-basic-auth|A mount with a basic auth login file answers 401 with a `WWW-Authenticate` challenge to no or unknown credentials, and serves listed ones, over h1, h2 (prior knowledge and tls) and h3; its files are not served through the public mount it sits inside by another spelling of its name (case, trailing dot or space); a ws upgrade to it, local or to a reverse proxy mount, meets the same basic auth over h1, h2 and h3, and the app's FILTER_PROTOCOL_CONNECTION for a proxied one
api-test-html-process|`lws_chunked_html_process()` over a page cut into lumps of every size, chunked and not: variables split across lumps are replaced, the chunk framing is right, and nothing is written outside the buffer; and interpreted files served over h1 and h2, a page read in several lumps and an empty one; and on one h1 keep-alive connection, a file served from a callback after an interpreted page goes out untransformed, without the page mount's caching; and a file mount with a protocol of its own still runs the interpreter with the interpreter's own per-session data
api-test-ws-pmd-takeover|permessage-deflate context takeover in both directions for each client offer of server_ / client_no_context_takeover: each end resets only what the negotiation says, by role, and the server's reply carries every option it took on
api-test-ss-server-upgrade|Secure Streams server ws upgrade over h1 and h2: the accepted stream, not the server template stream, hears LWSSSCS_SERVER_UPGRADE and then carries the ws tx
api-test-ss-server-accept|Secure Streams server accepted streams are destroyed with their connection, whatever the peer did: tcp connect and close, a partial h1 request, whole h1 and h2 transactions (the h2 network connection's own accepted stream too), the user code refusing one in LWSSSCS_CREATING over tls, plaintext, raw and h2, and destroying the server stream while a client is connected, on the default loop and on libuv
api-test-ss-sink|Creating a Secure Stream of a local sink streamtype with no sink, or one the sink refuses at LWSSSCS_SINK_JOIN or from the accepted sink stream's CREATING / CONNECTED, fails cleanly with nothing left; an accepted one goes when its source does
api-test-ss-policy|A rejected Secure Streams JSON policy, fetched or as an overlay, is torn down cleanly and leaves the policy in force alone; a valid one still parses after it
api-test-smtp-client|The sansIO SMTP session byte for byte, then lws_smtpc end to end against a fake relay: plaintext, implicit tls and STARTTLS, refusals, deferrals, timeouts, and clients and vhosts destroyed with mail queued (`-DLWS_WITH_EMAIL=1`)
api-test-webtransport|A WebTransport client opens its session with an h3 peer whose SETTINGS enable WebTransport and HTTP Datagrams, and refuses without sending the CONNECT when the peer's SETTINGS do not (that case needs `-DLWS_WITH_SYS_FAULT_INJECTION=1`)
api-test-client-proxy-redirect|An http client through an http CONNECT proxy, or SOCKS5, follows a relative redirect to the origin by the name and port it asked for, and a redirect to another port of the origin to that port, never to the proxy
api-test-client-next-address|A client whose connect to the first address the resolver gave is refused goes on to the next one: a fake nameserver gives both ::1 and 127.0.0.1, a server listens on only one of them, run once per family so whichever the host sorts first, one client is refused first
api-test-client-final-callback|Every client connection gets one final callback on its own protocol when the context is destroyed under it (CLIENT_CONNECTION_ERROR if it never connected, else CLOSED), on the default loop and libuv; a connect from it is refused, and a timer set on a wsi from the PROTOCOL_DESTROY its free runs is not left in the freed wsi
api-test-log-redact|With every log level on and captured, credentials never reach a log line: Authorization, Cookie (on h2 also as an HPACK dynamic table index) and an unknown X-Api-Key over h1, h2 and h3, a followed redirect's query string, and the PEM private key `lws_tls_alloc_pem_to_der_file()` converts, and a ws subprotocol offer carrying a token over h1 and h2 (only the vhost's own protocol names are logged in clear), and a request with credentials and a query through a reverse proxy mount
api-test-ota|`lws_ota` against a fake platform OTA layer: however an update ends (complete, image cut short, stream timeout with a flash write in flight, update mode refused), the system state returns to OPERATIONAL, the periodic check is rescheduled and the platform is aborted and let go of before the `lws_ota_t` goes; a context destroyed mid-write detaches the platform synchronously (`-DLWS_WITH_OTA=1` with the test key, see its README)
api-test-filename-purify|`lws_filename_purify_inplace()` turns hostile names (absolute, UNC and drive paths, `..`, dotfiles, control bytes, Windows device names) into one path component, identically on every platform, keeping the length (G-553)
api-test-form-post-file|minimal-http-server-form-post-file run as a fixture: absolute, `../` and `..\` upload filenames are stored inside its upload dir and nothing appears where they pointed; an existing name or a planted symlink is refused (409), a file over `--max-size` is refused (413) and removed, an upload abandoned mid-file leaves nothing, and exactly `--max-files` files are stored before uploads get 503 (G-552, G-554)
api-test-http-client-multipart|The client multipart form helpers against a raw server that records the request: forms with a file part and values longer than the write buffer arrive with exactly the declared Content-Length of body, never more for the server to read as the next request (G-619); an element too long for the element buffer, or with no `=`, is refused, and a file that changes size after it was sized fails the fill; a file that shrinks while it is being sent fails the fill instead of spinning, and one that grows sends only the length declared (G-029); names and file names with quotes, backslashes or CR / LF are refused by `lws_http_mp_sm` and `lws_client_http_multipart()`, and a file part's `filename=` is its own name without the local path (G-618)
